# Role-Based Assessment

> Role-Based Assessments are **AI-generated, role-specific evaluations** that test candidates across MCQ, written (subjective), and video response sections. Questions are dynamically generated by AI (Gemini) based on the job role, required skills, seniority level, and industry domain. Scoring for subjective and video sections is also AI-powered.

---

## Overview

| Property | Value |
|---|---|
| **Assessment Type** | `Role_Based` |
| **Total Duration** | 30 minutes |
| **Sections** | MCQ (60%), Subjective/Written (25%), Video Response (15%) |
| **Question Generation** | AI-powered (Gemini via FastAPI) |
| **Scoring** | MCQ: auto-graded. Subjective + Video: AI-scored (Gemini/Groq) |
| **Skill Combining** | 60% written + 40% video |
| **Speech-to-Text** | Deepgram for video transcription |
| **Domain** | Always `Universal` |

---

## Assessment Structure

| Section | Questions | Time | Weight | Scoring |
|---------|-----------|------|--------|--------|
| **Section A: MCQ** | 10–12 | 18 min | 60% | Auto-graded (correct option) |
| **Section B: Written Responses** | 2 | 8 min (4 min each) | 25% | AI-scored (0–5 scale per skill) |
| **Section C: Video Response** | 1 | 4 min | 15% | AI-scored (Deepgram STT + Gemini/Groq) |

---

## End-to-End Flow

1. Admin specifies: job role, skills, seniority, industry domain, optional job description
2. Backend calls FastAPI to generate AI questions (Gemini)
3. Generated questions (MCQ + subjective + video) are stored in the question bank
4. Assessment is assigned to students (standard flow: institute map, assessment set, assignments)
5. Student goes through ConfigCheck → BiometricCheck → Instructions → Fullscreen → takes assessment
6. MCQ section: standard option selection. Written section: text area responses. Video section: recorded video response
7. On submit, cron job triggers score calculation:
   - MCQ: auto-graded
   - Subjective: AI-scored via FastAPI (`calculate_role_based_subjective_score`)
   - Video: transcribed via Deepgram, then AI-scored via FastAPI (`calculate_role_based_video_score`)
8. Skill scores combined (60% written + 40% video)
9. Results stored in `roleBasedScores` table
10. PDF report generated via Handlebars + Puppeteer

## File Reference

### 1. Question Generation (FastAPI)

#### Router — `rolespecific.py`
**Path:** `fastapi-ai-engine/routers/rolespecific.py`

**Endpoints:**
- `POST /role_based/generate_questions` — generates full assessment via Gemini
- `POST /role_based/calculate_subjective_score` — AI scores a subjective answer
- `POST /role_based/calculate_video_score` — AI scores a video response (STT + analysis)

**Payload (`RoleBasedPayload`):**
```python
jobRole: str
skills: List[str]
seniority: str
industry_domain: str
region: Optional[str] = ""
jobDescription: Optional[str] = ""
```

#### Question Generator — `question_generator.py`
**Path:** `fastapi-ai-engine/QuestionGeneration/Role_Specific/question_generator.py`

**`RoleQuestionGenerator` class:**
- `generate_prompt()` — builds a comprehensive Gemini prompt that:
  - Specifies the assessment framework: 10–12 MCQs (18 min) + 2 Written (8 min) + 1 Video (4 min)
  - Requires **all provided skills** to be assessed across the 3 response types
  - Skill distribution: Written Q1 covers 40–50% of skills, Written Q2 covers another 40–50%, Video covers remaining + communication
  - Adapts by **seniority level**: Entry (0–2 yr), Intermediate (2–5 yr), Senior (5+ yr)
  - Adapts by **role type**: Technical, Creative, Management, Client-facing, Compliance
  - Adapts by **region**: regulatory/compliance context (North America, EU, APAC, Global)
  - Includes job description context when provided
  - Outputs structured JSON: `assessment_metadata`, `section_a_multiple_choice`, `section_b_written_responses`, `section_c_video_response`
- `generate_questions()` — calls Gemini API with retries (max 3), parses JSON response, validates structure

### 5. Score Calculation

#### Node.js Orchestration — `RoleBasedCalculations.js`
**Path:** `student-node/app/models/RoleBasedCalculations.js`

**`calculateMCQScore(mcqResponses)`**
- Deduplicates responses by `questionId`
- Looks up correct answer (option with `optionValue = 1`)
- Compares student's selected option ID
- Returns: `percentage_score`, `correct_answers`, `total_questions`, per-question details

**`calculateSubjectiveScore(subjectiveResponses, assessmentConfig, fastAPIService)`**
- For each subjective response, calls FastAPI `calculateRoleBasedSubjectiveScore()`:
  - Sends: question text, student answer, job description, skills list, industry domain
  - Receives: overall score (0–5), per-skill scores (0–5), job match score, detailed feedback
- Accumulates per-skill scores across questions, calculates averages
- Returns: `average_score`, `average_skill_scores`, per-question details with AI feedback

**`calculateVideoResponseScore(videoResponses, assessmentConfig, fastAPIService, assessment_assigned_id)`**
- For each video response:
  - Handles video upload retry logic (waits up to 3 × 60s for upload)
  - Generates presigned URL from OCI Object Storage
  - Calls FastAPI `calculateRoleBasedVideoScore()`:
    - STT via Deepgram → transcription
    - AI analysis via Gemini/Groq with scoring weights:
      - Content Relevance: 30%
      - Communication Skills: 25%
      - Technical Knowledge: 25%
      - Job Fit: 20%
    - Returns: overall score, skill scores, speech quality metrics, job match, recommendations
- Accumulates per-skill scores, calculates averages
- Returns: `average_overall_score`, `average_skill_scores`, speech quality metrics, per-question details

**`combineSkillScores(subjectiveScore, videoResponseScore, skillsList)`**
- Merges skill scores from both sections:
  - If both have a skill: `combined = (subjective × 0.6) + (video × 0.4)`
  - If only one has it: uses that score alone
- Returns: per-skill combined scores, details with source indication, average across all skills

**`storeRoleBasedScores(assessment_assigned_id, mcqScore, subjectiveScore, videoResponseScore)`**
- Handles retake detection (existing scores → `isRetake: true`)
- Deduplicates: deletes existing scores atomically before inserting
- Stores 3 rows in `roleBasedScores` table:
  - MCQ score row with `metadata: { correct_answers, total_questions, detailed_scores }`
  - Subjective score row with `metadata: { average_skill_scores, detailed_scores }`
  - Video score row with `metadata: { average_skill_scores, speech_quality_metrics, detailed_scores }`
- Marks `assessmentAssignedStudent.scoresCalculated = true`

#### FastAPI AI Scoring — `score_calculation.py`
**Path:** `fastapi-ai-engine/RoleBasedScorecalculation/score_calculation.py`

**`calculate_ai_subjective_score(question, user_answer, skills, job_description, client)`**
- AI prompt evaluates:
  - Overall score (0–5)
  - Per-skill scores (0–5) — only for skills relevant to the specific question
  - Job match score (0–5)
  - Detailed feedback: strengths, areas for improvement, job alignment, skill analysis, missing elements, recommendations
- Scoring criteria: 0–1 = Poor, 2 = Basic, 3 = Adequate, 4 = Good, 5 = Excellent
- Uses Gemini 2.5 Pro or Groq Llama 3.3 70B
- Falls back to 2.5 default scores if AI fails

**`combine_skill_scores(subjective_scores, video_scores, skills_list)`**
- Same 60/40 weighting as Node.js version
- Converts 0–5 scale to percentage (× 20)

**`generate_comprehensive_feedback(subjective_feedback, video_feedback, combined_skills, job_description)`**
- Generates overall assessment verdict based on average score:
  - ≥ 80%: Excellent
  - ≥ 70%: Good
  - ≥ 60%: Adequate
  - < 60%: Needs development
- Produces: skill gap analysis per skill, key strengths, critical areas, job readiness

**`get_skill_recommendation(skill, score)`**
- Per-skill recommendation text based on score thresholds

## Database Tables (Key)

| Table | Purpose |
|-------|--------|
| `questions` | AI-generated questions with `questionText`, linked to sections |
| `question_options` | MCQ options with `optionValue` (1 = correct) |
| `assessment_sections` | Section types: `MCQ Question`, `Subjective Question`, `Video Response`, `Coding Question` (Coding is an optional 4th section) |
| `assessment_config` | Per-set role config incl. `question_config` JSON (`{ mcqCount, subjectiveCount, videoCount, codingCount }`) — the per-section question counts chosen at creation. A count of **0 excludes that section** from the generated exam |
| `assessment_set` | Assessment pack with `roleName` stored |
| `assessment_question_map` | Maps generated questions to assessment set |
| `assessment_assigned_students` | Per-student assignment with `scoresCalculated` flag |
| `student_answers` | Responses: `answerText` for MCQ/subjective, `objectKey` for video (OCI path) |
| `role_based_scores` | Per-section scores with full `metadata` JSON (skill scores, detailed AI feedback, speech metrics). Supports `isRetake` |

## Key Concepts

- **AI-Generated Questions** — questions are dynamically generated by Gemini based on role parameters, not from a static question bank.
- **Selected-section score columns** — the admin score tables (StudentsTable / CandidateList / StudentReport) show a column per section **selected at creation** (`assessment_config.question_config` count > 0), not a hardcoded MCQ/Subjective/Video/Coding set. admin-node resolves this once per assessment (`getRoleBasedSelectedSections`, falling back to sections actually present in the exam) and returns it as `assessmentInfo.roleBasedSections`; each row's `roleBasedScores` always carries a key per selected section (score value, or `null` when not yet scored → rendered `-`). So a 0-question section never appears, and a selected section is visible even before submission/scoring. `overallScore` averages only the sections that have scores (`null` until any section is scored).
- **Skill Coverage Guarantee** — the prompt requires ALL provided skills to be assessed across MCQ + Written + Video sections.
- **Seniority Adaptation** — question difficulty and focus adapts: Entry level (fundamentals), Intermediate (complex problem-solving), Senior (strategic thinking).
- **Multi-Modal Assessment** — combines text-based MCQ, written analysis, and video communication in a single 30-minute assessment.
- **AI Scoring** — subjective and video responses are scored by AI (Gemini 2.5 Pro or Groq Llama 3.3 70B) with detailed per-skill feedback.
- **Speech-to-Text** — video responses are transcribed using Deepgram before AI analysis.
- **Skill Combining** — final per-skill score = 60% written assessment + 40% video assessment.
- **Video Upload Retry** — scoring waits up to 3 minutes for video uploads to complete before skipping.
- **Retake Support** — the system detects retakes and stores both original and retake scores separately.
- **Comprehensive Feedback** — AI provides strengths, areas for improvement, job alignment, skill gap analysis, and specific recommendations per response.
